"Our unit of analysis is the persistent change to a coding agent produced by software-engineering experience. We ask **which component retains it, what software evidence motivates it, when it is adopted, and whether its reuse improves later coding behavior**."
- look at *target taxonomy, coding signals, update mechanisms and evaluation methods*
- provides definitions for coding agents, self-evolving agents and self-evolving coding agents
- types of self-evolution (pg 9)
	- *architecture* SE determines how the agent’s capabilities are organized into task execution
		- *harness* SE
		- *workflow* SE
		- *multi-agent* SE
	- *model* SE incorporates coding experience into the parameters underlying action selection
	- *assets* SE turns coding experience and external knowledge into resources that remain available for subsequent execution
		- *memory* SE
		- *skill* SE turns coding knowledge into reusable guidance for action, updating the skill collection K𝑡
		- *tool* SE updates the executable utilities in T𝑡
		- *context* SE targets C𝑡 , the information, instructions, and environmental settings through which an agent encounters a coding task
